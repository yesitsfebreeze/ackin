# The one-level nesting rule holds only because a test fails when the walk is made recursive; the rule itself lives in one helper

A cartridge's subtree is walked **one level**: a nested cartridge is a direct
child directory of its parent's folder holding a `cartridge.json`. That rule
was an implementation accident inside `Cartridge::offered` — a `read_dir`
filter and nothing saying why it did not descend.

It is now `fn nested(root: &Path) -> Vec<PathBuf>` in `src/loader.rs`, directly
above `offered`, with the rule in its doc comment and the reason attached:
descending would make a grandchild's subtree visible to a grandparent that
never named it, which is the whole point of the answered fork. The file name is
`pub const MANIFEST: &str = "cartridge.json"`, shared by `nested`, `classify`
and `contracts`, so the three cannot drift.

The rule is pinned by `a_cartridge_two_levels_down_is_not_offered`, and the
test is worth more than its name because of how it is built: `vendor` is a
**plain directory**, not a cartridge, so `outer/vendor/inner`'s key is
unreachable from `outer` by any amount of re-exporting. It asserts both
directions in one place — `offered(outer)` is empty while
`offered(outer/vendor)` is `["inner.key"]`.

Both falsifications were run rather than assumed, and both are cheap to repeat:

- Make `nested` recursive → `a_cartridge_two_levels_down_is_not_offered`
  FAILED, 13 passed 1 failed.
- Remove the `passed_on` call from `loader::resolve` → four tests fail, not
  one: `an_export_that_names_nothing_inside_is_refused`,
  `a_cartridge_two_levels_down_is_not_offered`,
  `a_grandchild_key_reaches_the_top_only_through_every_level`,
  `an_unreadable_document_asks_for_nothing_knowable_not_for_nothing`.
  `test result: FAILED. 10 passed; 4 failed`.

A trap in the second: removing the call alone will not compile under
`warnings = "deny"`, because `passed_on` then has no caller and `root` no use.
The mutation needs `#[allow(dead_code)]` on `passed_on` and a rebind of `root`,
or the run reports `error: method passed_on is never used` and you learn
nothing about the tests. First attempt at it did exactly that.

`passed_on` is deliberately *not* run from `contracts()`, which calls
`Cartridge::read` directly: a re-export is checked once, where a cartridge
enters the graph through `resolve`. Re-checking it while listing contracts
would make one cartridge's bad `export` fail a listing about its neighbours.

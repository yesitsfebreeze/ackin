# An unreadable cartridge document must be absent from the listing, not empty in it, and carrying its error further breaks a test outside the footprint

`Host::manifest` read the document with `Err(_) => (Vec::new(), Grant::default())`,
so a document that would not read listed as a document that asked for nothing —
and an empty `Grant` is the *tightest* policy, the one state that must never
double as "could not be read".

What works: make `CartridgeInfo.grant` an `Option<Grant>`. `None` is "not read",
`Some(Grant::default())` is "asked for nothing", and `list()` prints the grant
columns only under `Some`. `list()` then answers how many documents were
unreadable and `Command::List` exits 1 when that count is nonzero, so a
listing can no longer report success on a profile it could not read.

**The ruled-out half, which costs a full gate run to find.** The obvious
companion change — carrying the resolve error into `CartridgeInfo.error` as
well, so a *disabled* entry with a bad document also prints why — fails the
suite. `tests::folders::malformed_manifests_fail_without_evaluating_entries`
deletes a `cartridge.json`, points a disabled profile entry at the folder, and
asserts `host.manifest().unwrap()[0].error.is_none()`. That assertion is a
proxy for "a disabled entry is not evaluated", and surfacing the document's own
error invalidates the proxy without touching the guarantee — which is
separately asserted two lines down by `fiber_of("disabled").is_none()`. Anyone
wanting the error text on a disabled entry must budget for editing
`src/tests/folders.rs`, which was outside every footprint on this board.

A live residue of the split: a disabled entry whose document will not read now
contributes to the non-zero exit while printing no message, because `error`
stays `None` for it. The exit is honest; the line is silent.

Second-order consequence, measured: once `list` exits non-zero on an unreadable
document, any probe running it under `set -eu` fails on a fixture that was
merely incomplete. `probe/old-documents-still-load.sh` copied fifteen real
manifests but not the one `ui:` file `ui/cartridge.json` declares, so the
listing's single pre-existing error became a script failure. The fix is to stub
the declared `ui` path in the fixture, which also makes the probe stronger: it
now proves fifteen documents read by exiting 0, rather than by eyeballing a
count beside one tolerated error.

# cargo build stalls with no CPU when macOS syspolicyd is pegged

Symptom: `cargo build` stops after ~10 crates. `cargo` sits at 0% CPU blocked in `jobserver::Client::acquire_allow_interrupts`; every `build-script-build` child is at 0% CPU and `sample` shows the whole process stack is a single frame, `_dyld_start`.

Cause: `syspolicyd` pegged at 100% CPU. Every newly linked Mach-O hangs in dyld waiting on it.

Minimal reproduction — `rustc -o h h.rs` on `fn main(){println!("hi");}` links fine, then running `h` never reaches `main` (killed by a 20s alarm, exit 142). Nothing to do with the crate under build.

Diagnosis order that works: `ps aux | grep cargo` (0% CPU, no rustc children) -> `sample <pid>` (jobserver read) -> list children (`build-script-build`, all 0%) -> `sample` a child (`_dyld_start` only) -> `ps aux | grep syspolicyd`.

# A document that will not read and an entry that will not load are two facts, and one field for both costs you either a silent exit or a test outside your footprint

This supersedes the ruled-out half of [[260912-8bef]]. That note recorded that
carrying the document's resolve error into `CartridgeInfo.error` breaks
`tests::folders::malformed_manifests_fail_without_evaluating_entries`, and
concluded the error had to stay swallowed for disabled entries. **That
conclusion was wrong, and the cost of it was a listing that exits 1 printing no
reason.** The constraint was real; the design was the problem.

The fix is two fields, not one. `CartridgeInfo.unread: Option<String>` is why
the *document* would not read; `CartridgeInfo.error: Option<String>` is what
evaluating the *entry* hit. They are different facts, known at different times
— `unread` is known whether or not anything tried to load the cartridge, which
is the whole premise of the document being data. `Host::manifest` fills
`unread` for disabled and enabled entries alike and suppresses `error` when it
would only repeat it, so the line says one thing once. The folders test's
`error.is_none()` is about evaluation, so it keeps passing untouched — no file
outside the footprint is needed, and nothing is bent. Conflating the two is the
same mistake as keeping the capability request in a second file.

**The second half, which no box caught and which the first pass papered over.**
`Host::manifest` read the document through `loader::resolve`, which resolves
the Lua entry and locates a declared `ui` file. So `grant.is_none()` meant "any
part of resolve failed", not "the document would not read" — and a manifest
declaring `"ui":"ui/index.ts"` whose file is simply absent parses perfectly and
made `zirkle list` exit 1. A real manifest in `~/dev/sys/builtin` hits this.
The first pass noticed the symptom only as a probe failing, and stubbed the
`ui` file in the fixture to get past it: the fixture was changed to fit the
code.

The seam that fixes it is in `Cartridge` itself. `Cartridge::document` is the
document checked against itself and nothing else — parse, binary basename,
name and entry *shape*, `ui` *shape*, and `check()`. `Cartridge::read` is that
plus the files it names: entry canonicalised, `ui` located, escape-the-folder
refused. The free `loader::document` wraps the first with `passed_on`, and the
listing uses it. A missing `ui` file now prints as what it is, beside the
declarations, with exit 0; the probe needs no stub.

Two consequences worth knowing before you touch this:

- `Declared` loses `export` and `grant` when you do this, because the listing
  stops reading them from `resolve`. Leave them and `warnings = "deny"` fails
  the build with `fields export and grant are never read`.
- `Cartridge::check` now runs *before* the entry and `ui` are located rather
  than after, so a document with both a declaration error and a missing file
  reports the declaration error. That is the better order — the document's own
  faults come first — but it does change which message some manifests print.

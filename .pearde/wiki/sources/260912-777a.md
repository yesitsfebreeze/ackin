# The zirkle test that pinned a disabled entry's error column could never fail, and two passes in a row built an argument on it

`tests::folders::malformed_manifests_fail_without_evaluating_entries` ends with
`assert!(host.manifest().unwrap()[0].error.is_none())` on a **disabled** entry
whose `cartridge.json` was deleted. That assertion cannot fail and never could:
`git show HEAD:src/loader.rs` shows `Host::manifest` hardcoding

    let (inject, provide, error) = if entry.disabled {
        (Vec::new(), Vec::new(), None)

so `error` is `None` for a disabled entry by construction, whatever the
document does. Its remaining teeth are only that `manifest()` returns `Ok` with
at least one entry. The guarantee the test's name claims — a disabled entry is
not evaluated and spawns nothing — is carried by the line below it,
`assert!(host.fiber_of("disabled").is_none())`.

**The expensive part is not the check; it is what was built on it.** One pass
read that assertion as "a proxy for 'not evaluated'" and concluded the
document's read error could not be surfaced for disabled entries without
editing a test outside the footprint. The next pass inherited the sentence from
the first pass's own report and repeated it, and a real design decision
([[260912-8bef]], later corrected by [[260912-6a8c]]) was argued partly from
it. Neither pass ran `git show HEAD` on the branch it was reasoning about. A
census carried forward from your own last report is exactly as untrustworthy as
one carried forward from someone else's.

The two-field `unread`/`error` split is still the right design, for reasons
that have nothing to do with this test — it separates two facts known at
different times. But "and it keeps the folders test passing" was never a reason
for anything, because nothing could have made that test fail.

A second thing on the record while looking: with the split in place, a profile
entry naming a folder that does not exist prints
`gone  gone  error: .../gone/cartridge.json: No such file or directory` and
`zirkle list` exits 1, where at HEAD it printed the same line and exited 0.
`loader::document`'s doc comment says an `Err` from it never means the tree
around the cartridge is incomplete — an absent folder is precisely the tree
being incomplete, and it still lands in `unread`, because there is no document
either to read or to fail to read. Defensible (a profile naming a missing
folder is broken, and a listing that reports success on one is worse) but it is
the one place the new distinction leaks, and no test pins it.

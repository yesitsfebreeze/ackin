# what does not clear a pegged syspolicyd

Symptom and diagnosis are in [[260912-ebde]]. This is what does **not** clear it, all re-tested after an hour of the peg:

- `codesign --force --sign -` on the freshly linked binary — still exits 142 under a 15s alarm. The check is not a signature check.
- Running a `cp` of an already-working system binary (`cp /bin/echo`) — also hangs. It is the newly created inode, not the compiler.
- Killing every stalled `cargo` and `build-script-build` on the machine, to release the XPC requests they were parked on. `syspolicyd` stayed at 100% with nothing left waiting on it, so the pile-up is a symptom and not the cause.

Consequence: a Rust build on this machine has no compile signal at all while the peg lasts, because build scripts are newly created binaries that must run. Restarting the daemon needs root; a worker without it should record the stall, leave the tree uncommitted, and make `cargo build` the first acceptance box for whoever builds next.

# the build signal is live on this host and the gate that says so is falsifiable

The peg is over and the board has a compiler again. Six runs of
`.pearde/prds/the-build-signal/probe/build-signal.sh` against
/Users/feb/dev/cartridge on 2026-09-12 between 16:26 and 16:28 CEST all printed
`signal=live` and exited 0: dyld OK, cargo-build OK, zirkle-help OK, cargo-test
OK (53 passed). Wall time 5s warm. `syspolicyd` is pid 93109 at 0.0% CPU; pid
498 is gone (`ps -p 498` exits 1). This is the host, not the lane worktree.

The gate was shown to be able to fail, which is the part worth keeping:

- Pointed at a crate that does not exist it prints `cargo-build FAILED rc=101`,
  `zirkle-help HUNG or missing`, `cargo-test FAILED rc=101`, `signal=dead`,
  exit 1. So a green run is a measurement and not a tautology.
- The cap fires: `perl -e 'alarm 2; exec(@ARGV)' sleep 60` returns rc=142 after
  2s, and stage 1 rebuilt around a binary that sleeps 300s prints
  `dyld HUNG rc=142` and exits 1 after 3s. No stage on this gate is reached by
  waiting.

Negative result, and it cost a pass to find: counting passed tests with
`grep -c '^test .* ok$'` undercounts. One run of the gate reported 52 on a crate
that `cargo test` reports 53 for on every direct run (three consecutive direct
runs, all `test result: ok. 53 passed; 0 failed`). libtest writes those per-test
lines from several threads and they interleave, so a line occasionally loses its
`^test` prefix or its trailing ` ok`. Count the per-binary summary lines
instead:

    sed -n 's/^test result: ok\. \([0-9][0-9]*\) passed.*/\1/p' LOG | awk '{t+=$1} END{print t+0}'

Stable at 53 across four runs of the gate after the change, and it still fails
closed: on a log with no summary line the sum is 0 and the stage reports
`FAILED 0 passed`. Anything on this board that gates on a test count parsed from
libtest stdout has the same bug.

# Creating a cartridge

Read architecture.txt for how the host runs cartridges and transport.txt for the
protocol. writing-good-cartridges.txt covers what makes one good.

A LUA CARTRIDGE

Two files in a folder under the cartridge root, here `hello/`.

cartridge.json:
{
  "name": "hello",
  "entry": "init.lua",
  "description": "Returns the JSON value supplied by its caller.",
  "provide": ["hello.echo"]
}

init.lua:
return {
  apply = function(ctx, config)
    ctx:provide("hello.echo", function(input) return input end)
  end,
}

Enable it in .cartridge/init.lua:
  return { {id = "hello", path = "hello"} }

and call it:
  cartridge run hello.echo '{"message":"hello"}'

The Lua ctx:

  ctx:provide(key, fn)            serve a key declared in `provide`
  ctx.<need>(args), ctx:call(key, args)
                                  call a key declared in `needs`
  ctx:on(name, fn)                listen to an event declared in `on`
  ctx:emit(name, data)            send to every listener, do not wait
  ctx:bail(name, data)            ask listeners in order; first non-nil answer
  ctx:parallel(name, data)        ask all; fail if any failed
  ctx:gather(name, data)          every answer as {from, data}
  ctx:notify(name, data)          emit and publish on the channel `name`
  ctx:publish(channel, data)
  ctx:subscribe(cartridge, channel, fn)   the cartridge must be a need's provider
  ctx:host(method, params)        status, snapshot, cartridges
  ctx:on_dispose(fn)              `apply` may also return a function to run on stop
  ctx:name(), ctx:needs()

A PROCESS CARTRIDGE

Any program that serves the protocol. init.lua:

  return cartridge.process("hello")

The program is found in the cartridge's .cartridge/bin, bin, beside the host
binary, then PATH; a name with a `/` is relative to the cartridge folder. A
command may be a string or a list: cartridge.process({"./run", "--flag"}).
The process runs in the project root, so a script finds its own files from its
own path. It runs inside its `grant`: exec must name any interpreter or
program it starts, read and write the paths it touches, net the hosts it
reaches.

In Rust, depend on the transport crate:

  [dependencies]
  transport = { path = "../cartridge.ctg/src/transport" }
  tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
  serde_json = "1"

  #[tokio::main]
  async fn main() {
      transport::cartridge::run(|ctx, _config| async move {
          ctx.provide("hello.echo", |input| async move { Ok(input) });
          Ok(())
      })
      .await;
  }

`Ctx` has the same operations as the Lua ctx: provide, call, on, emit, bail,
parallel, gather, notify, publish, subscribe, host, on_dispose, needs, name.

In TypeScript, copy src/transport/wire.ts into the cartridge:

  import { Wire } from "./wire";
  const wire = new Wire();
  wire.on("apply", async config => {});
  wire.on("hello.echo", async input => input);

with call, listen (events), emit, bail, gather, notify, publish, ask (host
queries), onClose. In another language, implement docs/transport.txt: bind
CARTRIDGE_SOCKET, accept `auth`, `apply`, `call`, `event`, `subscribe`,
`dispose`, and exit when stdin closes.

MANIFEST FIELDS

name and entry are required; entry is a relative .lua path inside the folder.

  description     one line of purpose
  provide         keys served
  needs           keys called; the profile can add more with `inject`
  on              events listened to
  grant           {read, write, net, exec}; absent grants nothing
  settings        dotted key -> {type, default, optional?, min?, max?, doc?}; see settings.txt
  config          author defaults laid over the declared ones
  selftest        a provided key that proves the cartridge's behaviour
  integration     a provided key that proves its wiring to a real dependency
  commands        label -> {argv, cwd, description?}; documentation, never run by the host
  binary          executable basename when it differs from the folder
  ui              a JavaScript or TypeScript client module inside the folder
  source          where the source lives

Keys are nonempty exact strings. Unknown fields are refused.

CONTRACTS

`cartridge verify` starts the profile and calls every `selftest` and
`integration` key with null; an error or `false` fails. `cartridge verify <id>`
starts only that cartridge and what its needs resolve to in the ledger.

THE HELP PAGE

Ship .cartridge/help.md: a title, two to four sentences on what the cartridge
owns and who reaches it, a "## Use" list of its keys and how to call them, and a
"## Read next" list of its own documents. `cartridge help <id>` prints it, then
the declarations from cartridge.json and every other document the cartridge
ships. Do not restate provide, needs or settings on the page.

LOCAL STATE

A cartridge keeps its state under the project's .cartridge/<its folder>. In its
own repository, .cartridge/.gitignore is a whitelist: `/*` ignores the folder
and `!/name` brings back durable entries (help.md, docs/, tests/).

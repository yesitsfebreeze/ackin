# Memos and system knowledge

The executable cartridge contract is cartridge.json. Plain-text guides under
docs/llms explain the system. The active Markdown memo record in .cartridge/memos
captures typed context, decisions, procedures, and system prompt contributions.
Do not invent a separate development JSON to repeat these sources.

RECORD FORMAT

A memo is UTF-8 Markdown with YAML frontmatter. Every memo has a declared kind
and a nonempty description. Paths are <kind>/<name>.md; leaf names are unique
across the record. [[name]] links resolve by leaf. A shipped cartridge memo is
addressed as @<cartridge>/<kind>/<name>.md. Workspace memos shadow shipped memos
with the same leaf; cartridge contributions are read-only through the record.

A kind:type memo declares a type using its type field. Read the actual declaration
before composing an instance; types and instructions live in the record itself.
The memo service's types operation returns those declarations. list filters by
kind; read returns a memo. index derives an overview, so avoid hand-maintained
memo indexes that drift away from the record.

Validated writes check the record before atomically replacing a file. Supply
expected_revision when editing a revision you read to avoid overwriting concurrent
changes. Do not bypass validation merely because Markdown can be written directly.
Credentials, databases, and unbounded execution logs do not belong in memos.

DISCOVERY AND USAGE

usage declarations describe actions such as read, edit, run, and compose. A memo
may include uses entries linking to a usage with nonempty when phrases. These
are discovery metadata, not authorization or executable hooks. resolve finds
ranked references for a usage and situation and includes revision digests.
coverage reports missing declarations; observe records evidence about use/outcome.
No match means no declared coverage, not that no relevant context exists.

Call the MCP memo tool with arguments such as:
  {"op":"types"}
  {"op":"list","kind":"routine"}
  {"op":"read","path":"routine/create-cartridge.md"}
  {"op":"resolve","usage":"run","query":"create a cartridge"}

A new memo write has this shape:
  {"op":"write","path":"routine/example.md","body":"<complete Markdown>"}
The full body must include required frontmatter. On edits, carry the revision
returned by discovery/read in expected_revision according to the tool schema.
Inspect tools/list for the exact current schema before integration work.

SYSTEM CONTEXT

Enabled kind:system memos contribute to the harness's system prompt according
to the system type and composition rules. Historical notes are evidence, not
instructions merely because search returned them. The harness also composes
other context and memory; the memo record is not the memory cartridge's database.
Existing records are preserved, not reset or merged with seed content on startup.

CREATING-CARTRIDGES ROUTINE

The validated routine is .cartridge/memos/routine/create-cartridge.md. Read it
through memo read. It uses kind:routine, a description, and run-usage metadata,
with Inputs, Do, Check, and Failure sections as the routine type requires.
It links the detailed docs/llms/creating-cartridges.txt guide and identifies the
manifest, composition, real protocol tests, and submodule commits needed to finish.
Update the procedure when an actual authoring run reveals a missing step.

MIGRATED KNOWLEDGE

The active record was copied from sys and its current guidance updated for the
new source directory. Historical entries retain their context. Live old sessions
can still write to the preserved legacy record; the migration snapshot is not
a bidirectional synchronizer. Reconcile later writes before deleting that archive.
See MIGRATION.md and note/cartridge-development-home.md for the transition.

# ASP: the agent's one interface to the world

ASP (Agent Server Protocol) is the fabric with a better protocol. The fabric
was one graph of everything the composition can reach, ranked by how well a
node matches and how much it is used. ASP is that graph, served by the base
itself, and it adds what the fabric's protocol lacked: a typed identity for
every node, a registry of the types each cartridge declares, a contributor and
a revision on every fact, staleness, and actions. An agent asks ASP about an
entity and gets one merged answer from every loaded cartridge that knows
something about it.

ASP keeps no store. It asks the live providers on every request. Installing a
cartridge adds its types and its facts; removing it removes both, and nothing
has to be retracted.

ENTITIES

An entity is `scheme:key`, for example `file:src/a.rs` or
`symbol:src/a.rs#main`. One cartridge owns a scheme. The owner defines the
canonical key, and every other cartridge uses that form. An entity exists
while at least one loaded cartridge asserts it.

DECLARATION

  "events": { "asp.files": {} },
  "listen": ["asp.files"],
  "asp": {
    "schemes":    { "file": { "description": "a workspace file", "owner": true } },
    "edges":      { "contains": { "description": "the file holds the symbol" } },
    "attributes": { "files.bytes": {} },
    "actions":    [ { "name": "open", "applies_to": "file", "effect": "read",
                      "tool": "tool.read", "args": { "path": "${key}" } } ],
    "search":     true
  }

  schemes     the schemes this cartridge asserts nodes of. ASP sends it every
              expand of an entity in one of them. `owner: true` makes it the
              scheme's owner; the first loaded owner wins, and `types` reports
              a second one under `clashes`.
  edges       the edge kinds it asserts.
  attributes  the attributes it sets on nodes. Each name starts with the
              cartridge's own name, so two cartridges never collide.
  actions     what an agent can do with an entity of `applies_to`. An action
              is a pointer to a tool event. `args` is that tool's input, as
              an agent passes it to the tool, never the `{op, input, context}`
              envelope a harness wraps around it; in `args`, the strings
              `${entity}` and `${key}` stand for the entity.
  search      whether it answers `{op: "search"}`.

A cartridge with an `asp` block listens to exactly one `asp.<name>` event. The
base refuses the manifest otherwise, and refuses a scheme or edge kind that is
not lowercase letters, digits and `-`.

WHAT A PROVIDER ANSWERS

ASP sends `{op: "expand", entity}` or `{op: "search", query, limit}` to the
provider's `asp.<name>` event. The provider answers

  { nodes: [ { id, revision?, name?, description?, when?, tags?, attributes? } ],
    edges: [ { from, to, kind, revision? } ] }

or nil when it has nothing. `revision` is the revision of the expanded entity
the fact was computed against: a content hash, a commit. `name`,
`description`, `when` and `tags` are what search matches and ranks.

ASP holds every answer against the provider's declaration. A node of a scheme
it did not declare, an attribute it did not declare or an edge kind it did not
declare refuses the provider's whole answer, and the refusal names it.

WHAT THE BASE CONTRIBUTES

The base is a provider too, under the name `host`, for what only it knows in
full: `cartridge:<id>` for every loaded cartridge, `tool:<name>` for every
`tool.<name>` event, and a `provides` edge from the cartridge to its tool. Its
search matches a tool by its name and description. `types` also lists every
declared event under `events`, with its owner, description and schema: an
event is a type of the same world, declared in the same manifest.

REQUESTS

  {op: "types"}                         the registry: schemes with owner and
                                        contributors, edge kinds, attributes,
                                        actions, search providers, clashes
  {op: "expand", entity, depth?, limit?}
                                        nodes, edges, actions and sources.
                                        depth 1 to 4 (default 1) follows edges;
                                        limit caps nodes at 256
  {op: "search", query, limit?}         every search provider's nodes, merged
                                        and ranked: hits of {node, score, why},
                                        and the edges between the hits
  {op: "actions", entity}               the actions bound to the entity
  {op: "act", entity, action}           run one, as `{op: "call", input: args}`
                                        with no caller context, so a tool that
                                        needs one refuses. The tool event is the whole
                                        dispatch, so whatever answers or
                                        refuses it, policy included, reaches
                                        the caller unchanged

Every node lists its `contributors`, and every edge names its `contributor`,
each with the `revision` it answered against. When the scheme owner's revision
of the expanded entity differs, the fact comes back with `stale: true`; it is
never dropped. `sources` names every provider asked and its state: `available`,
`unavailable` (it failed or timed out; its facts are absent) or `refused`.

REACHING IT

  cartridge call asp '{"op":"expand","entity":"file:src/a.rs"}'
  cartridge.host("asp", { op = "types" })       from a cartridge's init.lua

  tool.asp {op: "describe" | "call", input}     the agent's tool, among its other tools

`asp` is the base's own service key, so no cartridge may declare it as an event.
`tool.asp` is an event the base itself owns and listens to: a cartridge that
needs `tool.*` or `tool.asp` gets it like any other tool, and `cartridge.events()`
names `host` as its owner. It speaks the tool envelope (`describe`, `call`,
`cancel`) and answers `{content, error}`, where `content` is the ASP answer as
JSON text.

Only the command line may `act`. A cartridge that asks `act` through
`cartridge.host` or `tool.asp` is refused, because an action names a tool, and
an agent runs tools through its own dispatch, where policy is asked. ASP tells
the agent which tool and which arguments; it never becomes a way around policy.

RANKING

Search ranks with the fabric's formula: matched words in a node's name and id
(weight 3), `when` (3), `tags` (2) and description (1), times a standing of
1 + ln(1 + uses). A node whose words do not match keeps its provider's order
below every node that matched. Use counts come from the event ring; until the
ring indexes events by entity, every standing is 1.

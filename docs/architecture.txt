# Architecture

THE BASE

The base loads and wires; it is not on the path of events.

  src/loader/     cartridge.json (document.rs) and the profile (entries.rs):
                  installed cartridges, init.lua over them, config.lua over each entry
  src/host/       the running composition
    plan.rs       what an entry declares, its settled config, the event catalogue
                  and the directory each node is handed
    mod.rs        slots, start order, launch checks, reconcile, restart, stop, host queries
    process.rs    starting a node inside its sandbox
    socket.rs     socket locations, the host socket and its methods
    watch.rs      restarting on source changes, reconciling on profile changes
    run.rs        `run` and `verify`: start, send, stop
  src/node/       a node: init.lua with the `cartridge` global, native modules, helpers
  src/ledger/     every cartridge installed under the cartridge root
  src/lua/        one Lua state per cartridge and per configuration file, with its limits
  src/trust/      what this machine will evaluate or spawn, by SHA-256
  src/sandbox/    a grant compiled into an operating-system policy;
    linux.rs      the Linux boundary: Landlock plus a seccomp socket filter
  src/settings/   settings files and the base's own settings
  src/trace/      trace ids and the diagnostics sink
  src/error/      the typed error every host-side failure becomes
  src/cli/        the command line
  src/transport/  the internal wire between the base and its nodes

THE PROFILE

Every folder under the cartridge root (`--dir`, default the project) holding a
`cartridge.json` is installed and starts disabled. `.cartridge/init.lua`
returns entries `{id, path, config?, disabled?}` that enable and configure
them.
`~/.cartridge/config.lua` and `.cartridge/config.lua` map entry ids to config
laid over each entry.

Nothing in a project is evaluated until `cartridge trust` has recorded a
SHA-256 for it, in `~/.cartridge/trust` (or `$CARTRIDGE_HOME/trust`), keyed
by the canonical directory: every `*.lua` and every `cartridge.json` under
it, manifests included because the grant comes from them. Setup records the
profile it wrote and each cartridge it chose; a file the tree already held
stays untrusted until the person reviews it. A file passes when
any trusted directory above it recorded its current hash. Files under
`~/.cartridge` are the person's own, and a home that is not an absolute path
is refused rather than quietly disabling all of this. Listing a manifest takes
no trust; planning a cartridge does.

PLANNING AND CHECKS

For each enabled entry the base reads cartridge.json: the events it defines,
listens to and needs, its grant and its settled configuration. It never runs
the entry itself. From all enabled entries it builds the event catalogue and
refuses, before anything starts: an event defined twice (the later entry
fails) and a `listen` or `needs` naming an event nobody defines.

LIFECYCLE

  disabled  not listed, or `disabled = true`
  waiting   a needed event has no active listener yet
  starting  being started and applied
  active    serving
  stopping  being disposed
  failed    refused at planning, would not start or apply, or exited on its own

The base starts every waiting cartridge whose needs all have active listeners,
wave by wave. `cartridge status` names what a waiting cartridge waits for.

NODES

Each cartridge runs as a node: the base binary re-run with `node`, inside a
sandbox built from the cartridge's `grant` (macOS: sandbox-exec; Linux: the
`__confine` trampoline, which applies Landlock and a seccomp socket filter to
itself and then becomes the node), with access to the base's socket
directory. The node runs init.lua in the sandboxed Lua interpreter with the
`cartridge` global injected, loads the native modules the entry asks for, and
serves the cartridge on its own socket. Its stdin closes when the base goes
away; its stderr is recorded. When a node fails to start, the error carries the
last lines it wrote. The state is the node's own: its memory cap and
instruction budget are spent by this cartridge alone. Lua that runs
host.lua_instruction_budget instructions without handing control back — an
apply, a handler between two waits — is refused with "exceeded its budget of N
Lua instructions". The budget counts Lua instructions, not a host call Lua is
waiting on, and a cartridge that catches its own refusal and keeps running
leaves the process with status 70.

Each node leads its own process group, and the programs it spawns join it.
Stopping a node disposes it, closes its stdin, waits shutdown_timeout_secs,
and kills the whole group, so nothing a cartridge started outlives it. The
terminal's signals reach the base, not the nodes: an interrupt or a terminate
stops `run`, `launch`, `mcp`, `daemon`, `verify` and `doctor` the way
`cartridge stop` does. While `launch`'s agent runs, the interrupt is the
agent's.

A node reads no trust store: the base hands it the SHA-256 of the entry it
verified, and the node refuses an entry whose bytes no longer match. The
node's sandbox grant is what keeps it away from the store, not the check. The
one trust read left in a node is its own settling of host settings — it reads
a `config.lua` it can reach, and warns and uses declared defaults when it
cannot. A node is started with a cleared environment — an allow-list in
`src/host/process.rs` plus the variables that name the node, scrubbed before
any helper exists — so no secret of the person's shell and no base credential
reaches a cartridge or its helpers.

Each base run has a directory under `$XDG_RUNTIME_DIR/cartridge` or
`/tmp/cartridge-<uid>` holding one socket per node, stable for the run, and
`host.sock`, the base's own socket for nodes and the command line. A base that
serves a project links `<project tag>.sock` to it and writes its token beside
it, 0600, so the command line finds it. The base mints a token per edge: one
for each cartridge that may send an event to a listener, and one for each node
to ask the base. Each node's own socket is opened by a token minted for it
alone, so the base's admin token never enters a node. A listener's node knows
which events each token it accepts may send. The base sends its own events
(`run`, `call`, `send`, `verify`) through
the same code the nodes send with, to active listeners only.

Both directories are created 0700 and narrowed again if found wider. Each
socket is bound under a narrowed umask, so it is owner-only from the moment
the kernel creates it. A name already held is refused unless it is this
user's own socket: another uid, a link to another uid, or a file that is not
a socket refuses the bind and is left where it is.

WHAT THE SANDBOX DOES NOT COVER

Both platforms: `grant.net` names hosts and no kernel policy filters by host,
so a nonempty `net` allows outbound network and an empty one allows none.

macOS: an interpreter linked against other installations — a Homebrew python
reaching /opt/homebrew/opt — needs those paths in `grant.read`; only its own
installation prefix is implicit.

Linux: below Landlock ABI V9 (Linux 7.1) a unix socket named by a path is not
gated, so a node can connect to any socket on the machine — another project's
base socket (still behind its token), the docker socket, an ssh agent. The node
says which ABI it obtained on its stderr at every start below V9. A grant naming
a path that does not exist yet is refused: Landlock is inode-based.
`grant.exec: ["*"]` is refused unless `grant.read` names `/`, because Landlock
needs read access on a program to execute it.

RELOAD

A changed source restarts its node: dispose, wait, start on the same socket
with a fresh node token. Other nodes keep running and reconnect. A changed
`init.lua` or `config.lua` reconciles the profile: removed or changed entries
stop, new ones start, and running nodes whose directory changed receive it.
A source or profile edited after it was trusted fails with the untrusted
refusal instead of restarting; `cartridge trust`, then `cartridge reload`.

# Architecture

THE HOST

The host loads and wires; it is not on the path of calls or events.

  src/loader/     cartridge.json (document.rs) and the profile (entries.rs):
                  installed cartridges, init.lua over them, config.lua over each entry
  src/host/       the running composition
    plan.rs       what an entry runs as, its settled config, and its directory
    mod.rs        slots, start order, reconcile, restart, stop, host queries
    process.rs    starting a process cartridge inside its sandbox
    lua.rs        serving a Lua cartridge in-process, and the Lua ctx API
    socket.rs     socket locations, the host socket and its methods
    watch.rs      restarting on source changes, reconciling on profile changes
    run.rs        `run` and `verify`: start, call, stop
  src/ledger.rs   every cartridge installed under the cartridge root
  src/lua.rs      the sandboxed Lua interpreter and the `cartridge` global
  src/sandbox.rs  a grant compiled into an operating-system policy
  src/settings/   settings files and the host's own settings
  src/trace.rs    trace ids and the diagnostics sink
  src/cli/        the command line
  transport/      the protocol crate: JSON-RPC peer, sockets, the cartridge side, settings

THE PROFILE

Every folder under the cartridge root (`--dir`, default `builtin`) holding a
`cartridge.json` is installed and starts disabled. `.cartridge/init.lua`
returns entries `{id, path, config?, inject?, disabled?}` that enable and
configure them; a `path` may also name a bare `.lua` file. `inject` adds keys to
an entry's needs; `inject = {"tool.*"}` names every key with that prefix another
enabled entry provides. `~/.cartridge/config.lua` and `.cartridge/config.lua`
map entry ids to config laid over each entry.

PLANNING

For each enabled entry the host evaluates its Lua entry. A table
`{provide?, needs?, on?, apply}` is a Lua cartridge; `cartridge.process(cmd,
{inject?})` is a process cartridge, its program resolved in the cartridge's
`.cartridge/bin`, `bin`, beside the host, then PATH. Where `cartridge.json`
declares `provide`, `needs` or `on`, it wins over the table. Each key is
provided by one entry; a second provider fails the later entry.

LIFECYCLE

  disabled  not listed, or `disabled = true`
  waiting   a need has no active provider yet
  starting  being started and applied
  active    serving
  stopping  being disposed
  failed    would not plan, start or apply, or exited on its own

The host starts every waiting cartridge whose needs all have active providers,
wave by wave. A cycle, or a need nothing provides, leaves the cartridges
waiting; `cartridge status` names what they wait for.

SOCKETS AND TOKENS

Each host run has a directory under `$XDG_RUNTIME_DIR/cartridge` or
`/tmp/cartridge-<uid>` holding one socket per cartridge, stable for the run,
and `host.sock`, where cartridges ask the host questions. The project's host
socket for the command line sits beside it, with the host token in a 0600 file.
Tokens are minted per edge: consumer to provider for calls, emitter to listener
for events, cartridge to host for host queries. docs/transport.txt has the wire.

PROCESS CARTRIDGES

A process cartridge runs in the project root, inside a sandbox built from its
`grant` (macOS: sandbox-exec; Linux is refused until Landlock is implemented),
with read and write access to the host's socket directory. It gets
CARTRIDGE_SOCKET, CARTRIDGE_HOST_TOKEN and CARTRIDGE_CONNECT_TIMEOUT_SECS, a
stdin that closes when the host goes away, and a stderr the host records. The
host waits until the socket answers, authenticates, and calls `apply`. When it
fails to start, the error carries the last lines it wrote to stderr.

LUA CARTRIDGES

A Lua cartridge's `apply(ctx, config)` runs in the host's interpreter and is
served on its own socket like any other cartridge, so other cartridges cannot
tell the difference. The interpreter has no `io`, no `require`, and an `os`
that only reads the clock and the environment.

RELOAD

A changed source restarts its cartridge: dispose, wait, start on the same socket
with the same tokens. Dependents keep running and reconnect. A changed
`init.lua` or `config.lua` reconciles the profile: removed or changed entries
stop, new ones start, and running cartridges whose directory changed receive it.

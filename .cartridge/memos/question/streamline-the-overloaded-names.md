## Question

The grammar memos flag names that do two or three jobs. Which of these get
streamlined, and to what? The answer determines which cartridges, services and
docs get renamed or merged, and whether a new tool key is born.

## Options

- `memory`: the cartridge name collides with the memo record's territory and
  the core-resident per-profile memory bank. Rename the cartridge (e.g. its
  engine name) or rename the bank concept — one keeps the word.
- `landscape`: settled on 2026-09-12 — memo stays the only door, and the fourth
  name for the same thing is gone: the op, the crate module and
  `sdk::Host::landscape` all say landscape, nothing says inventory. See
  [[the-landscape-owns-the-graph]].
- `proxy`: `builtin/proxy` (the harness request proxy) and the router's HTTP
  proxy share the word. Rename one config surface or the cartridge.

Recommendation: rename `memory` first (highest misread risk, cheapest — one
cartridge folder and manifest), keep the landscape behind `tool.memo` (no
second door to guard), rename the router's HTTP proxy surface to a distinct
word. Each rename is its own work memo once decided.
